<Note>
  This documentation is for **white-label integrators** who want to host their own
  branded event listing and ticket checkout, while UnderPass handles tickets,
  orders, payments, and settlements behind the scenes.
</Note>

## What you get

A small, stable HTTP API that lets you:

- **List events** for your tenant account
- **Render an event detail page** with selling stages, ticket types, and organizer info
- **Validate promo codes**
- **Start a checkout session** that redirects the buyer to a hosted payment page
- **Poll order status** after payment to render a confirmation screen

You don't need to handle payments, settlement, tax calculation, invoices, or
ticket delivery — UnderPass owns all of that.

## How it fits together

```
┌──────────────────┐    HTTPS     ┌──────────────────────────┐
│ Your frontend    │ ───────────► │ UnderPass Public API     │
│ (any framework)  │ ◄─────────── │ api.underpass.com.co     │
└──────────────────┘              └──────────────────────────┘
                                              │
                                              ▼
                                  ┌──────────────────────────┐
                                  │ Payment provider (Bold)  │
                                  │ + invoicing + settlement │
                                  └──────────────────────────┘
```

Your frontend never talks to the payment provider directly. After a buyer
submits checkout, you redirect them to a URL we return — they pay there, then
land back on a URL you provide. You poll us to render the confirmation page.

## The five endpoints you need

| Verb | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/events/public?account_id=…` | List your tenant's published events |
| `GET` | `/api/events/public/{slug}` | Single event detail (with tickets) |
| `POST` | `/api/checkout/allowed-document-types` | Filter document types per locality |
| `POST` | `/api/checkout/start` | Create an order, get a payment redirect URL |
| `GET` | `/api/checkout/status/{orderId}` | Poll order status post-payment |

Optional: `POST /api/promo-codes/validate` if your events use promo codes.

## Identity & scoping

All requests are scoped to your **tenant account UUID** (`account_id`), provided
during onboarding. There's no per-user authentication for these endpoints —
buyers don't need accounts to purchase tickets. The `account_id` on listing
endpoints filters to your events; ticket type IDs on checkout endpoints
implicitly scope to your tenant because tickets belong to events that belong
to your account.

For higher-trust integrations (rate-limit increases, audit logging, write
operations beyond ticket purchase) we issue per-tenant API keys — sent as
`X-Underpass-Api-Key`. Not required for the public surface above.
