This walkthrough takes you from "blank page" to "buyer purchased a ticket"
in four calls. All snippets are plain `fetch`; no SDK required.

## Prerequisites

- Your **tenant `account_id`** (UUID) from UnderPass onboarding
- The API base URL: `https://api.underpass.com.co`
  (dev: `https://api-dev.underpass.com.co`)
- A **session key** per browser: an opaque string of 8 to 128 characters (a UUID in an
  `httpOnly` cookie is ideal). It owns the buyer's reservation and waiting-room pass.

## 1. List events

Show the buyer what's for sale. `account_id` is required so the response is
scoped to your tenant.

```js
const API = "https://api.underpass.com.co";
const ACCOUNT_ID = "00000000-0000-0000-0000-000000000000"; // your tenant UUID

async function listEvents() {
  const res = await fetch(
    `${API}/api/events/public?account_id=${ACCOUNT_ID}&limit=50`,
    { headers: { Accept: "application/json" } },
  );
  if (!res.ok) throw new Error(`List failed: ${res.status}`);
  const { data } = await res.json();
  return data.events; // → EventDto[] (see API reference for full shape)
}

// Hero image lives in `event.media[]`. Pick the one with `is_primary === true`.
function heroImage(event) {
  return event.media.find((m) => m.is_primary)?.url ?? event.media[0]?.url;
}
```

Render the list however you like — there's no required UI. Note that `data` is
`{ events: EventDto[], pagination: { page, limit, total, total_pages } }`.

## 2. Fetch event detail (with tickets)

When a buyer picks an event, fetch the detail page. This includes selling
stages, ticket types, prices, and locality info.

```js
async function getEvent(slug) {
  const res = await fetch(
    `${API}/api/events/public/${encodeURIComponent(slug)}`,
    { headers: { Accept: "application/json" } },
  );
  if (!res.ok) throw new Error(`Get failed: ${res.status}`);
  const { data } = await res.json();
  return data; // → { id, name, slug, ticketAvailability: [...], performances: [...], ... }
}
```

`ticketAvailability[]` is **one row per ticket type × selling stage** that is on sale right
now: `{ ticketType, sellingStage, stagePricing, available, reserved }`. Price is
`stagePricing.price` (a decimal string, parse it), stock is `available` (already net of other
buyers' reservations), and `ticketType.locality` tells you the section. Group rows by locality
and render the picker.

Three things the event may carry that change the picker: several `performances[]` (a date
selector first, see [Multi-date events](/guides/performances)), a locality with
`seating: "NUMBERED"` ([Numbered seating](/guides/seating)), and `waiting_room: true`
([Waiting room](/guides/waiting-room)). An event with none of them works exactly as below.

<Warning>
  Respect the purchase limits when rendering the picker: cap each ticket type's
  selector at `ticket_type.max_per_order`, and the whole cart at the event's
  `max_tickets_per_order` (both `null` = unlimited). These limits are also
  enforced server-side at checkout start — bypassing the UI just earns a `400`.
</Warning>

## 3. Reserve the selection

The moment the buyer continues with a selection, reserve it. The tickets are theirs for the
event's hold window (`event.hold_minutes`, 10 by default) while they fill in the form, and
nobody else can buy them.

```js
async function reserve({ eventId, items }) {
  const res = await fetch(`${API}/api/checkout/holds`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      event_id: eventId,
      session_key: SESSION_KEY,
      items, // [{ ticket_type_id, selling_stage_id, quantity }]
    }),
  });
  if (!res.ok) throw new Error(`Reserve failed: ${res.status}`);
  const { data } = await res.json();
  return data; // → { id, status: "ACTIVE", expires_at, items: [...] }
}
```

Show a countdown from `expires_at`. A `400 INSUFFICIENT_TICKETS` here is the right moment to
tell the buyer, not after they typed their details. Details in [Reservations](/guides/reservations).

## 4. Start checkout

After the form, create the order with the hold:

```js
async function startCheckout({ eventId, items, customer, holdId }) {
  const res = await fetch(`${API}/api/checkout/start`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      event_id: eventId,
      items, // the same [{ ticket_type_id, selling_stage_id, quantity }]
      customer, // { email, name, phone, document_type, document_number }
      accept_terms: true,
      hold_id: holdId,
      success_url: "https://your.site/orders/confirm",
      cancel_url: "https://your.site/orders/cancelled",
    }),
  });
  if (!res.ok) throw new Error(`Checkout failed: ${res.status}`);
  const { data } = await res.json();
  return data; // → { order_id, payment_provider, redirect_url, total_amount }
}
```

An error here carries a machine `code` you should surface to the buyer instead of a
generic failure: `409 HOLD_EXPIRED` (the reservation ran out: back to the picker),
`400 INSUFFICIENT_TICKETS`, `MAX_PER_ORDER_EXCEEDED` / `MAX_TICKETS_PER_ORDER_EXCEEDED`
(per-order limits), `MAX_TICKETS_PER_EMAIL_EXCEEDED` (the email already holds the maximum for
this event), `ATTENDEE_COUNT_MISMATCH`. See the API reference for the
`{ code, message, detail }` error shape.

Redirect the buyer to `redirect_url`. They pay on the provider's hosted checkout page (Bold
or ePayco, whichever the organizer uses) and land back on your `success_url` or
`cancel_url`. The order total includes the buyer-facing service fee; see
[Fees & installments](/guides/fees-and-installments).

If `total_amount === 0` (courtesy / fully discounted), there's no payment
step — `redirect_url` will be your confirmation URL directly.

## 5. Poll order status

After the buyer returns from the payment page, you don't know yet if the
payment cleared. Poll the status endpoint until it resolves:

```js
async function pollOrder(orderId, { intervalMs = 2000, maxAttempts = 30 } = {}) {
  for (let i = 0; i < maxAttempts; i++) {
    const res = await fetch(`${API}/api/checkout/status/${orderId}`);
    if (!res.ok) throw new Error(`Status failed: ${res.status}`);
    const { data } = await res.json();
    if (["CONFIRMED", "PARTIALLY_PAID", "CANCELLED", "EXPIRED"].includes(data.status)) {
      return data;
    }
    await new Promise((r) => setTimeout(r, intervalMs));
  }
  return { status: "PENDING" }; // give up: show "te avisamos por correo cuando confirme"
}
```

`CONFIRMED` and `PARTIALLY_PAID` (first installment paid) are both a sale. Tickets are
emailed by UnderPass when the order is fully paid; you never deliver them yourself.

## End-to-end

```js
const events = await listEvents();
const event = await getEvent(events[0].slug);
const row = event.ticketAvailability[0];
const items = [{ ticket_type_id: row.ticketType.id, selling_stage_id: row.sellingStage.id, quantity: 2 }];
const hold = await reserve({ eventId: event.id, items });
const session = await startCheckout({
  eventId: event.id,
  items,
  holdId: hold.id,
  customer: {
    email: "buyer@example.com",
    name: "Jane Buyer",
    phone: "+573001112233",
    document_type: "CC",
    document_number: "123456789",
  },
});
window.location.href = session.redirect_url;
// ... buyer pays, returns to your `success_url` with `?order_id=...`
const result = await pollOrder(session.order_id);
console.log(result.status); // "CONFIRMED"
```

### Promo codes

Validate a code before the user submits checkout. Some codes unlock hidden
selling stages — re-fetch the event with `?unlocked_stages=...` to reveal them.

```js
async function validatePromoCode({ eventId, code }) {
  const res = await fetch(`${API}/api/promo-codes/validate`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ event_id: eventId, code }),
  });
  const { data } = await res.json();
  return data;
  // → { valid, effect_type, discount, unlocked_stages?, ... }
}
```

Pass the validated code on the `startCheckout` payload as `promo_code` so the
backend re-applies the discount on order creation.

### Sales links (private presales / promoter attribution)

A sales link is a per-event code that unlocks private selling stages and/or
attributes the sale to a promoter. Validate before showing tickets:

```js
async function validateSalesLink({ eventId, code }) {
  const res = await fetch(`${API}/api/sales-links/validate`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ event_id: eventId, code }),
  });
  const { data } = await res.json();
  return data;
}
```

When valid, fetch the event with `?link={code}` so the response includes the
unlocked private tickets:

```js
const event = await fetch(`${API}/api/events/public/${slug}?link=${code}`)
  .then((r) => r.json()).then((b) => b.data);
```

### Referrals

Show a referral program panel on event pages so buyers see what they'd earn
for sharing:

```js
async function getReferralProgram(eventId) {
  const res = await fetch(`${API}/api/referrals/program/${eventId}`);
  if (res.status === 404) return null; // event has no program
  const { data } = await res.json();
  return data; // → { tiers: [...], terms, ... }
}
```

If the buyer arrived via `?ref={code}`, validate it before checkout:

```js
async function validateReferralCode({ eventId, code }) {
  const res = await fetch(`${API}/api/referrals/validate`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ event_id: eventId, code }),
  });
  const { data } = await res.json();
  return data;
}
```

Pass the validated code on the `startCheckout` payload as `referral_code` for
attribution.
