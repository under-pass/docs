---

UnderPass keeps one view of conversions across every storefront for ads attribution, fraud
prevention and platform reporting. Every white-label frontend therefore fires **the same
funnel events, with the same parameters, at the same points**. The platform also sends the two
conversion events **server-side** (Meta Conversions API, TikTok Events API) keyed by the order
id; your browser events must carry that same id so each platform counts the pair once.

This page is the contract. Implement it once.

## Where pixel ids come from

`GET /api/events/public/{slug}` exposes `pixelIntegration`:

```json
{
  "pixelIntegration": {
    "meta_pixel_id": "1493256712205722, 987654321",
    "tiktok_pixel_id": "C1A2B3C4D5E6",
    "google_analytics_id": null,
    "google_tag_manager_id": null,
    "twitter_pixel_id": null,
    "linkedin_partner_id": null
  }
}
```

`pixelIntegration` may be `null`; each field is independently nullable. `meta_pixel_id` may be
**comma-separated**: initialize each id. Server-side credentials (CAPI / Events API tokens, test
event codes) never appear here; UnderPass uses them on its side.

## Pixels to initialize

On every page of the buyer journey (event detail → tickets → checkout → confirmation):

| Pixel | When |
| --- | --- |
| **Platform Meta pixel** `749891594864955` | Always, first |
| Event's `meta_pixel_id` (each id) | When set |
| Event's `tiktok_pixel_id` | When set |

Without the platform pixel UnderPass loses cross-tenant attribution and fraud alerts degrade.

## Events to fire

| Event | When | Meta | TikTok | Dedup key |
| --- | --- | --- | --- | --- |
| Page view | On init | `PageView` | `page()` | — |
| View content | Event page loads (and the ticket page, for deep links that skip it) | `ViewContent` | `ViewContent` | — |
| Add to cart | Buyer picks tickets and continues to checkout | `AddToCart` | `AddToCart` | — |
| Initiate checkout | **When `checkout/start` returns** the order | `InitiateCheckout` | `InitiateCheckout` | `order_id` |
| Purchase | **Once per order, on its first successful payment** (`CONFIRMED` or `PARTIALLY_PAID`) | `Purchase` | `CompletePayment` | `order_id` |

### Parameters

Every event carries the same shape on both platforms:

```js
// Meta
{ content_type: "product", content_name: event.name,
  content_ids: [ticketTypeId, …],
  contents: [{ id: ticketTypeId, quantity, item_price }],
  num_items, value, currency: "COP" }

// TikTok
{ content_type: "product", description: event.name,
  contents: [{ content_id: ticketTypeId, content_name, price, quantity }],
  value, currency: "COP" }
```

- `contents` is one line per **ticket type** (not per selling stage).
- `value` is integer COP: the cheapest visible price on ViewContent, the cart subtotal on
  AddToCart, and `total_amount` from `checkout/start` on InitiateCheckout and Purchase (the
  order total, not the first installment).
- The dedup key goes in the options argument: Meta `{ eventID: order_id }`, TikTok
  `{ event_id: order_id }`.

<Warning>
  Names and values must match the server exactly, or the platforms count twice. TikTok's purchase
  event is still named `CompletePayment` on both sides; do not rename it on your own.
</Warning>

## Reference implementation

```js
const PLATFORM_META_PIXEL_ID = "749891594864955";
const TIKTOK_PURCHASE = "CompletePayment";

export function injectPixels({ metaPixelId, tiktokPixelId } = {}) {
  const ids = [PLATFORM_META_PIXEL_ID, ...(metaPixelId || "").split(",").map((s) => s.trim()).filter(Boolean)];
  window.__metaPixelIds = [...new Set(ids)];
  /* standard Meta base snippet here */
  window.__metaPixelIds.forEach((id) => fbq("init", id));
  fbq("track", "PageView");
  if (tiktokPixelId) {
    /* standard TikTok base snippet here */
    ttq.load(tiktokPixelId);
    ttq.page();
  }
}

function fire(meta, tiktok, p, dedupId) {
  const metaParams = {
    content_type: "product", content_name: p.eventName,
    content_ids: p.contents.map((c) => c.id),
    contents: p.contents.map((c) => ({ id: c.id, quantity: c.quantity, item_price: c.price })),
    num_items: p.contents.reduce((n, c) => n + c.quantity, 0),
    value: p.value, currency: "COP",
  };
  const ttParams = {
    content_type: "product", description: p.eventName,
    contents: p.contents.map((c) => ({ content_id: c.id, content_name: c.name, price: c.price, quantity: c.quantity })),
    value: p.value, currency: "COP",
  };
  window.fbq?.("track", meta, metaParams, dedupId ? { eventID: dedupId } : undefined);
  window.ttq?.track?.(tiktok, ttParams, dedupId ? { event_id: dedupId } : undefined);
}

export const trackViewContent = (p) => fire("ViewContent", "ViewContent", p);
export const trackAddToCart = (p) => fire("AddToCart", "AddToCart", p);
export const trackInitiateCheckout = (p, orderId) => fire("InitiateCheckout", "InitiateCheckout", p, orderId);
export const trackPurchase = (p, orderId) => fire("Purchase", TIKTOK_PURCHASE, p, orderId);
```

`p` is `{ eventName, contents: [{ id, name, price, quantity }], value }`.

## Advanced matching (identify)

Once you know who the buyer is (checkout submit, confirmation page), tell both pixels
**before** the event you want enriched. This is what lifts match quality beyond cookies and IP.

```js
export async function identifyPixelUser({ email, phone, firstName, lastName, externalId }) {
  // Meta: re-init each pixel with plaintext user data; the pixel hashes it.
  const userData = { country: "co", em: email?.trim().toLowerCase(), ph: phone?.replace(/\D/g, ""),
                     fn: firstName?.toLowerCase(), ln: lastName?.toLowerCase(), external_id: externalId };
  (window.__metaPixelIds ?? []).forEach((id) => window.fbq?.("init", id, userData));

  // TikTok: SHA-256 hashes (email lowercased, phone in E.164 with "+").
  const sha = async (v) => Array.from(new Uint8Array(await crypto.subtle.digest("SHA-256",
    new TextEncoder().encode(v))), (b) => b.toString(16).padStart(2, "0")).join("");
  window.ttq?.identify?.({
    email: email && (await sha(email.trim().toLowerCase())),
    phone_number: phone && (await sha("+" + phone.replace(/\D/g, ""))),
    external_id: externalId && (await sha(externalId)),
  });
}
```

Use the buyer's document number as `externalId`. Call it with the same data only once.

## Server-side half

UnderPass sends `InitiateCheckout` when the order is created and `Purchase` /
`CompletePayment` on the first payment, from its servers, to the platform pixel, to each of the
organizer's Meta pixels with a Conversions API token, and to each TikTok pixel with an Events
API token. Those events match the ad click through the `tracking` object you send on
`checkout/start` (`fbc`, `fbp`, `ttclid`, `ttp`, IP, user agent) and the buyer's hashed email,
phone and document. See [Marketing attribution](/guides/attribution).

## In the buyer journey

| Step | Page / action | Call |
| --- | --- | --- |
| 1 | Event page loads | `injectPixels(...)`, `trackViewContent` |
| 2 | Ticket page loads | `injectPixels(...)` (and `trackViewContent` only if the buyer skipped the event page) |
| 3 | "Continuar" with a selection | `trackAddToCart` |
| 4 | Checkout submit | `identifyPixelUser` with the form data, then call `/api/checkout/start` |
| 5 | `/api/checkout/start` returns | `trackInitiateCheckout(p, order_id)`, then redirect |
| 6 | Buyer returns to `success_url` | `injectPixels(...)`, `identifyPixelUser`, poll `/api/checkout/status/{order_id}` |
| 7 | Status is `CONFIRMED` or `PARTIALLY_PAID` for the first time | `trackPurchase(p, order_id)` exactly once (remember it per order) |

## Common mistakes

<AccordionGroup>
  <Accordion title="Firing Purchase on the success_url page load">
    The buyer lands back before the webhook confirms. Firing on load counts every cancelled
    payment as a purchase. Wait for the status poll.
  </Accordion>
  <Accordion title="Firing Purchase only on CONFIRMED">
    An installment order is PARTIALLY_PAID after its first payment and stays so for weeks. The
    conversion happened; fire then. Never fire again on later installments.
  </Accordion>
  <Accordion title="InitiateCheckout before the order exists">
    Fire it when `checkout/start` returns, with `order_id` as the dedup key and `total_amount`
    as value. Firing on the button click leaves the server-side event unmatched.
  </Accordion>
  <Accordion title="Forgetting the platform Meta pixel">
    `749891594864955` first, then the organizer's pixels.
  </Accordion>
  <Accordion title="Wrong currency or fractional value">
    `"COP"`, integer values, no division by 100.
  </Accordion>
  <Accordion title="Renaming CompletePayment to Purchase on TikTok">
    The server sends `CompletePayment`. A different name breaks the dedup and the event counts twice.
  </Accordion>
</AccordionGroup>

## Not needed

`Lead`, `CompleteRegistration`, `AddPaymentInfo` and subscription events. If you want custom
events for your own analytics, fire them on your own pixel, not on the platform pixel.
